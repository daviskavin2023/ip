# PRD 2026-10-06：Tunnel / 优选 IP 卡片加 7 天可用性

状态：用户已确认（只要 7 天，不要 30 天），实施中。

## 为什么改
3024 的项目详情里有"可用性"色块条，用户希望 Tunnel 总览和优选 IP 大屏的域名卡片也有。目前这两个页面只有"当前"状态，没有历史，无法画。

## 方案
- **采集**：`tunnel-panel.py` 的后台巡检（约每 60 秒对 46 个域名的内网地址做一次 HTTP 探测，已有）每轮顺手累加当天的 `up/total`，写入 `/var/lib/tunnel-panel/uptime.json`（原子写，保留 14 天）。
  - 计入：隧道 healthy 且探测成功 = up；隧道异常或探测失败 = 非 up；非 HTTP 服务（未探测）不计。
  - 日期按北京时间（UTC+8）切日。
- **读取**：`tunnel-panel.py` 与 `web_ui.py` 各加只读 `GET /api/uptime`，返回最近 7 天日期列表和各域名每天的 `[up,total]`。
- **展示**：两个页面的域名卡片各加一行：7 个色块（绿=全部正常、黄=≥90%、红=<90%、灰=无样本）+ "7 天 xx%"。无样本显示 `--`，不用 100% 掩盖。
- 注意：探测的是**内网服务本身**是否可用，不是经过优选 IP 的外网路径。

## 影响范围
- 只新增文件和接口，不改现有接口字段、不动优选/回滚/转换逻辑。
- 卡片高度整体加一行（Tunnel 144→168px，优选 IP 域名卡 120→144px），所有卡片同步变化。

## 验收
- 部署后 `uptime.json` 持续累加，`/api/uptime` 两个端口都能返回。
- 无样本的天显示灰色，页面不把"没数据"显示成 100%。
- 375/390/412/1280 零横向滚动；卡片等高。
- 历史无法回填（旧日志只记失败、不记成功），所以最初几天只有当天一格有色，之后逐天补满 7 格。

## 作废方案
- 30 天条；回填旧日志；让 3024 提供数据。
